# Project Workflow (GStack Framework)

## Global Rules
- Always use the gstack browser for web browsing tasks by triggering the local server.
- Follow the YC startup-engineering loop: Think -> Plan -> Build -> Review -> Test -> Ship.

## Available Slash Commands (GStack Roles)
- /office-hours : Activate product strategy mode. Interrogate the feature request, understand user pain, and find the "10-star" version of the product.
- /spec : Turn vague intent into a precise, executable specification across five phases.
- /plan-ceo-review : Challenge scope, set strict priorities, and reduce waste from a founder/CEO perspective.
- /plan-eng-review : Lock down technical architecture, data flows, database changes, and test matrices before writing code.
- /review : Act as a paranoid staff engineer. Perform a deep code-review on the current branch to catch bugs, UI slop, and edge-cases before a PR.
- /investigate : Systematic root-cause debugger for tricky issues.
- /qa : Launch the headless browser daemon to run end-to-end user flow testing on localhost or staging.
- /ship : Prepare the code for production deployment and release.
