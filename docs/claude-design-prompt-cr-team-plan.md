# פרומפט ל-Claude Design — הגשת תוכניות CR צוותיות

> העתק את הטקסט שבתיבה למטה ל-Claude Design. מבוסס על [docs/spec-cr-team-plan-submission.md](./spec-cr-team-plan-submission.md).

```
עצב מסך/מודול חדש בשם "הגשת תוכניות CR" עבור DeployCenter — מערכת SaaS דו-לשונית
(עברית/RTL בעיקר) לניהול לילות שחרור גרסאות תוכנה. קהל היעד: ראשי צוותי פיתוח/QA/תפעול
שממלאים טפסים תחת לחץ זמן, ומנהלי גרסה שסוקרים את התוצר המאוחד.

## שפת עיצוב — עקבי לשפת המערכת הקיימת
- RTL מלא, פונט Rubik (עברית) / Fira Code (מונוספייס למספרי CR/קוד).
- פלטת Indigo מודרנית ונקייה: רקע אפליקציה כמעט-לבן (#F7F8FB), כרטיסים לבנים,
  מותג אינדיגו עמוק (גוון oklch(0.55 0.19 265), כהה יותר בהובר), סיידבר כהה
  קבוע (#14152A) בניגוד לתוכן הבהיר.
- פינות עגולות בינוניות (8–12px), צללים עדינים מאוד (לא דרמטיים), מעברים מהירים (~150ms).
- צ'יפים/תגיות סטטוס בצבע מלא-שקוף (10–12% אלפא) עם טקסט בגוון המלא — לא צבעים שטוחים.
- טון כללי: כלי עבודה רציני ומהיר, לא "קונסיומר" מרשים מדי — אנשים ממלאים את זה
  תוך כדי משמרת לילה, לא גולשים בפנאי.

## העיקרון המוביל של הפיצ'ר (חשוב לעיצוב, לא רק לתוכן)
זה טופס "exception-first" — רוב הפריטים (CR-ים) לא דורשים מילוי מלא, רק אישור מהיר
של "אין השפעה מיוחדת". העיצוב חייב להבליט ויזואלית את מסלול-המהיר (הרוב) בלי
להסתיר את מסלול-המלא (המיעוט) — למשל קלפים/מצבים שמתקפלים/מתרחבים לפי תוכן, לא
טופס ארוך קבוע שתמיד נראה מפחיד.

## המסכים לעצב (בסדר עדיפות)

### מסך 1 — "רשימת העבודה שלי" (Team Work Queue)
מסך הפתיחה של ראש צוות. **לא טופס — רשימת מטלות (checklist) עם פס התקדמות.**
- כותרת עם שם גרסה + שם צוות.
- פס התקדמות בולט (X מתוך N תוכניות הושלמו), עם אחוזים.
- רשימת CR-ים כשורות/כרטיסים: מספר CR, שם CR, תג סטטוס (✅ הושלם / ⏳ ממתין),
  קליק פותח את ה-CR.
- כפתור ראשי "סיימתי הגשת תוכניות" — במצב disabled (עמום, עם טולטיפ מסביר) עד
  שכל השורות מסומנות הושלם, ואז הופך לפעיל/בולט.
- מקרה קצה לעצב: מצב "אין CR-ים לצוות שלך בגרסה זו" (empty state ידידותי, לא הודעת שגיאה).

### מסך 2 — טופס CR בודד, שער סיווג ראשוני
המסך הקריטי ביותר לחוויה: שאלה בודדת גדולה וברורה —
"האם קיימת השפעה תפעולית מיוחדת ל-CR זה?" עם שתי כפתורי-בחירה גדולים (לא/כן).
- בבחירת "לא": מיד מופיע תקציר קצר ("CR זה נכלל בהטמעה הרגילה...") וכפתור
  אישור בודד — עצב את זה כך שברור חזותית שזה "כמעט סיימת, לחיצה אחת ואתה חוזר לרשימה".
- בבחירת "כן": שאר הטופס נפתח בהדרגה (accordion / sections מתרחבים), לא קופץ הכל בבת אחת.

### מסך 3 — טופס CR מלא (המסלול "כן")
טופס מרובה-סקשנים, אבל כל סקשן צריך מבנה קומפקטי משלו (לא טופס ארוך ואחיד):
1. **מה משתנה** — multi-select צ'יפים (קוד/פרמטר/הרשאה/Setup/ממשק/Job/סקריפט/הסבת נתונים/קובץ).
2. **פעולות חריגות** — רשימת "כרטיסי פעולה" ניתנים להוספה (0..N), כל אחד עם: סוג פעולה
   (dropdown), תיאור (textarea שגדל אוטומטית לפי תוכן), מתי מתבצע (בחירת עוגן זמן: T-1/ליל
   גרסה/בוקר גרסה/יום אחרי), תלות לוגית (dropdown של עוגנים כמו "אחרי Deploy WIZ"), ותיוג
   "נדרש גורם ייעודי?" עם בורר שם.
3. **תנאים מקדימים** — multi-select צ'יפים.
4. **בדיקות חריגות** — שתי שאלות כן/לא נפרדות (ליל גרסה / יום אחרי) שכל אחת פותחת שדה טקסט.
5. **נקודות בקרה (Monitoring)** — רשימה ניתנת להוספה: סוג (Interface/Table/Job/Report/
   Queue/File/Other) + שם + הערת בקרה. עצב כטבלה קומפקטית או כרטיסי-mini.
6. **Rollback** — בחירה מרשימה סגורה + הערה קצרה.
7. **תקציר וסגירה** — לפני האישור הסופי, מסך תקציר קריא (לא עוד טופס) שמרכז את כל
   מה שהוזן בבליטים קצרים, עם כפתור "אשר תוכנית CR" גדול בתחתית.

### מסך 4 — סקירת תוכנית מאוחדת (למנהל גרסה)
מסך לאחר שכל הצוותים סיימו: מציג רשימה מקובצת לפי צוות, ובתוכה את הפעולות
החריגות שנגזרו, מקובצות לפי עוגן-זמן (ליל גרסה / בוקר אחרי וכו') — עיצוב דמוי
timeline/עמודות לפי עוגן, לא טבלה שטוחה. כולל תקציר מספרי עליון (X CR ללא השפעה
מיוחדת, Y CR עם השפעה, Z משימות חריגות נגזרו).

## מצבים ואינטראקציות נדרשים
- Empty state (צוות בלי CR-ים).
- מצב disabled עם הסבר (כפתור סיום לפני שהכול הושלם).
- מעברי accordion חלקים בין שאלת השער לשאר הטופס.
- אינדיקציית "נשמר"/"טיוטה" עדינה (לא מודל חוסם).
- מובייל/טאבלט לא קריטי — עיצוב שולחני קודם (רוב המשתמשים בעמדת עבודה).

## מה לא לעצב
- אל תעצב דשבורד Monitoring/HyperCare עצמו — רק את שדות ההזנה של נקודות הבקרה.
- אל תמציא לוגיקת הרשאות/תפקידים חדשה — זה כבר קיים במערכת.
- אל תשנה את פלטת סטטוס-המשימות/עדיפות/חומרה הקיימת (כחול/ענבר/אדום/ירוק/סגול) —
  היא domain-specific ולא חלק מהעדכון הזה.
```
